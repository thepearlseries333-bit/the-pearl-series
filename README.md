# The Pearl Series — منصة تعليمية للمشتركين
**Five Stars in English — الأستاذ Youssef Osman**

منصة ويب ثابتة (HTML + CSS + JavaScript) تعمل على GitHub Pages، وتستخدم Firebase
للدخول بالبريد الإلكتروني وإدارة الاشتراكات وفتح/قفل الأقسام.

## 3) مخطط قاعدة البيانات (Firestore)

### `members/{email}` — المشتركون (معرّف المستند = البريد بحروف صغيرة)
| الحقل | النوع | مثال |
|---|---|---|
| `name` | string | `"أحمد محمد"` |
| `phone` | string | `"01012345678"` |
| `status` | string | `"active"` أو `"suspended"` |
| `sections` | array | `["p1","p2"]` أو `["*"]` لكل الأقسام |
| `expiresAt` | timestamp / null | `2027-01-31` — و `null` تعني اشتراك دائم |
| `notes` | string | `"دفع 300ج فودافون كاش"` |
| `createdAt` / `updatedAt` | timestamp | تلقائي |

### `admins/{email}` — المشرفون
مستند فارغ (أو `{ role: "admin" }`) بمعرّف = بريدك. **يُضاف من Firebase Console فقط**،
والقواعد تمنع الكتابة عليه من الموقع نهائيًا.

### `sections/{sectionId}` — كتالوج الأقسام (اختياري)
`{ ar, en, group, icon, order }`. إن كانت المجموعة فارغة يستخدم الموقع القائمة
الموجودة في `assets/js/catalog.js`. أضِفها في Firestore إن أردت تعديل الأقسام بدون تعديل كود.

### `content/{sectionId}` — روابط الملفات الحقيقية 🔐 **الأهم**
`{ url: "sections/p1-a7f3c2e9.html" }`
لا يُقرأ هذا المستند إلا لمشترك: نشط + غير منتهٍ + هذا القسم ضمن صفوفه.
تُدار من زر **«روابط الأقسام»** في لوحة الإدارة.

## 4) طريقة الدخول: حساب Google (أساسية) + كود دخول (احتياطية)

**جرّبنا أولًا "رابط بالبريد" وفشل عمليًا:** خدمة الإرسال المدمجة في Firebase لم
تُسلّم الرسائل إطلاقًا (اختُبرت على بريدين، ولم تصل حتى إلى Spam). لذلك:

**1) الدخول بحساب Google — الزر الأساسي**
- لا كلمة مرور تُتداول، ولا اعتماد على وصول أي رسالة بريد.
- ولي الأمر يرسل لك بريد Google الخاص به على واتساب، وأنت تضيفه في لوحة الإدارة.
- الدخول بحساب Google **لا يعني الوصول للمحتوى**: من ليس بريده في `members`
  يرى "هذا البريد غير مُفعّل"، وقواعد Firestore ترفض له كل شيء.
- مشاركة الحساب تعني مشاركة حساب Google الشخصي — رادع حقيقي.

**2) كود الدخول (بريد + كلمة مرور) — للاحتياط**
لولي أمر بلا حساب Google. أنت تنشئ الحساب من لوحة الإدارة، والنظام يولّد كودًا
عشوائيًا، وتُرسله على واتساب بزر جاهز. الكود محفوظ في مستند المشترك لتذكيره به.

> تغيير كود مشترك لاحقًا لا يتم من اللوحة (يحتاج صلاحيات خادم)؛ يتم من
> Firebase Console → Authentication → المستخدم.

الجلسة محفوظة (`browserLocalPersistence`) فلا يُطلب الدخول في كل مرة.

## 5) الأمان — اقرأ هذا الجزء بتركيز

### أ) ظهور `apiKey` على GitHub أمر طبيعي وليس ثغرة
مفاتيح Firebase للويب **ليست أسرارًا**؛ هي عنوان يقول للمتصفح: «اتصل بمشروع رقم كذا».
كل موقع Firebase في العالم يعرضها في كود الصفحة. الحماية الحقيقية طبقتان:

1. **Authentication** — يجيب على سؤال: *من أنت؟*
2. **Firestore Security Rules** — تجيب على: *وماذا يحق لك أن تقرأ؟*

فلو أخذ شخص مفاتيحك وبنى بها صفحة، سيصطدم بنفس القواعد ولن يقرأ شيئًا.
**الشيء الوحيد الممنوع رفعه** هو ملف Service Account (`*-firebase-adminsdk-*.json`)
إن استخدمته لاحقًا في سكربتات — هذا سر حقيقي.

### ب) نقطة صدق مهمة: GitHub Pages يقدّم ملفات مكشوفة
قواعد Firestore تحمي **البيانات**، لكنها لا تحمي **ملف HTML ثابتًا** داخل مستودعك.
لو عرف أحدهم الرابط المباشر لملف قسم، سيفتحه. لذلك طبّقنا طبقتين:

1. **اسم ملف غير قابل للتخمين + رابطه مخزّن في `content` المحميّة.**
   من ليس مشتركًا لا يستطيع حتى معرفة اسم الملف (يحصل على `permission-denied`).
   لهذا سمّينا ملف النموذج `found-demo7f3a91.html` وليس `found.html`.
2. **`section-guard.js`** — سطران في أعلى كل ملف قسم يخفيان الصفحة حتى يتأكد
   من الدخول والصلاحية. طبقة إضافية، وليست البديل عن الأولى.

> **للحماية القصوى لاحقًا** (إن أردت): ارفع ملفات الأقسام إلى **Firebase Storage**
> بقواعد صلاحيات، بدلًا من مجلد GitHub. حينها لا وجود لرابط عام إطلاقًا.
> الكود الحالي مهيأ لذلك: يكفي أن يحوي `content/{id}.url` رابط Storage.

### ج) لا يوجد تسجيل ذاتي
أي شخص يستطيع *طلب* رابط دخول (هذا سلوك Firebase الطبيعي)، لكنه بعد الدخول
لن يجد بريده في `members` فيظهر له: **«هذا البريد غير مُفعّل»** ولا يقرأ أي محتوى.

## 6) خطوات التشغيل (بالتفصيل — لا تحتاج خبرة برمجية)

### الخطوة 1: إنشاء مشروع Firebase
1. افتح [console.firebase.google.com](https://console.firebase.google.com) → **Add project**.
2. اسم المشروع: `pearl-series` → Continue → (يمكنك إيقاف Google Analytics) → **Create**.

### الخطوة 2: تفعيل الدخول بالبريد
1. من القائمة اليسرى: **Build → Authentication → Get started**.
2. اختر **Email/Password** → شغّل المفتاح الأول، **والأهم**: شغّل
   **Email link (passwordless sign-in)** → **Save**.
3. تبويب **Settings → Authorized domains → Add domain** وأضِف نطاق موقعك:
   `<username>.github.io` (وأيضًا `localhost` للتجربة المحلية).
   ⚠️ بدون هذه الخطوة سترى خطأ `unauthorized-continue-uri`.

### الخطوة 3: إنشاء قاعدة البيانات
1. **Build → Firestore Database → Create database**.
2. اختر **Start in production mode** (لا تختر test mode) → اختر موقعًا قريبًا
   (`europe-west` مناسب لمصر) → **Enable**.

### الخطوة 4: رفع قواعد الأمان
1. في Firestore → تبويب **Rules**.
2. امسح كل الموجود، وافتح ملف `firestore.rules` من مشروعك وانسخ محتواه بالكامل والصقه.
3. **Publish**.

### الخطوة 5: جعل بريدك أدمن
1. في Firestore → تبويب **Data** → **Start collection** → اسم المجموعة: `admins`.
2. **Document ID**: بريدك بحروف صغيرة (مثال: `youssef@gmail.com`).
3. أضِف حقلًا: `role` (string) = `admin` → **Save**.

### الخطوة 6: نسخ إعدادات المشروع إلى الكود
1. **⚙️ Project settings → General** → انزل لأسفل → **Your apps** → أيقونة الويب `</>`.
2. اسم التطبيق: `pearl-web` → **Register app**.
3. انسخ قيم `firebaseConfig` والصقها في ملف `firebase/firebase-config.js`
   بدلًا من كلمات `PASTE_...`.
4. في نفس الملف عدّل `whatsapp` إلى رقمك بصيغة دولية بدون `+`
   (مثال: `201234567890`).

### الخطوة 7: الرفع على GitHub Pages
افتح PowerShell داخل مجلد المشروع:

```bash
git init
git add .
git commit -m "The Pearl Series platform"
git branch -M main
git remote add origin https://github.com/<USERNAME>/pearl-series.git
git push -u origin main
```

ثم في صفحة المستودع على GitHub:
**Settings → Pages → Source: Deploy from a branch → Branch: `main` / `(root)` → Save.**
بعد دقيقتين يعمل الموقع على: `https://<USERNAME>.github.io/pearl-series/`

> تذكّر إضافة `<USERNAME>.github.io` في **Authorized domains** (الخطوة 2).

### الخطوة 8: أول تجربة
1. افتح الموقع، اكتب بريدك (بريد الأدمن) → اضغط «إرسال رابط الدخول».
2. افتح بريدك (راجع Spam) واضغط الرابط → ستُرجَع للمنصة.
3. ستظهر لك شاشة «هذا البريد غير مُفعّل» — طبيعي! لأن بريدك في `admins` وليس في `members`.
   افتح `admin/admin.html` مباشرة، وستدخل كأدمن.
4. من لوحة الإدارة: **+ إضافة مشترك** → أضِف بريدك أيضًا كمشترك تجريبي بكل الأقسام،
   ثم **روابط الأقسام** → في حقل «التأسيس» اكتب `sections/found-demo7f3a91.html` → حفظ.
5. ارجع للصفحة الرئيسية → بطاقة «التأسيس» صارت مفتوحة وتعمل. 🎉

## 7) دورة العمل اليومية عندك

1. ولي الأمر يدفع (فودافون كاش / إنستاباي) ويرسل لك البريد الإلكتروني.
2. تفتح `admin/admin.html` → **+ إضافة مشترك** → البريد + الاسم + الهاتف +
   تحديد الصفوف + زر **«+ سنة»** لتاريخ الانتهاء → **حفظ**.
3. ترسل له رابط الموقع. يدخل ببريده فورًا دون أي إجراء منك.
4. عند انتهاء الاشتراك: يظهر تلقائيًا محجوبًا. للتجديد اضغط **«+سنة»** أمام اسمه.
5. لإيقاف حساب مشترك للمشاركة: تعديل → الحالة = **موقوف**.

## 8) إضافة ملفات أقسامك الجاهزة

ملفاتك self-contained، وهذا ممتاز. لكل ملف:

1. **أعِد تسميته** برمز عشوائي: `p3-9d41be7c.html` وضعه في مجلد `sections/`.
2. أضِف هذين السطرين داخل `<head>` (وعدّل `data-section` لمعرّف القسم):
   ```html
   <style id="pearl-guard-style">body{visibility:hidden}</style>
   <script type="module" src="../assets/js/section-guard.js" data-section="p3"></script>
   ```
3. من لوحة الإدارة → **روابط الأقسام** → اكتب `sections/p3-9d41be7c.html` أمام الصف الثالث → حفظ.

**لماذا فتحنا الأقسام في تبويب جديد بدل `iframe`؟**
ملفاتك تحتوي CSS و JS خاصًا بها، و`iframe` كان سيخلق مشاكل في الأحجام والصوت
(`Web Speech API` يتصرف بشكل غريب داخل الإطارات على الموبايل) وفي الطباعة.
التبويب الجديد يعطي مساحة كاملة لكل درس ويحفظ استقلال ملفاتك تمامًا.

## 9) أفكار للتوسّع لاحقًا (غير مطلوبة الآن)

- **بوابة دفع فعلية** (Paymob): تحتاج Cloud Functions ليتحقق الخادم من الدفع ثم
  يكتب في `members` — لا يمكن عملها بأمان من المتصفح وحده.
- **تتبّع تقدّم الطالب**: مجموعة `progress/{email}/{sectionId}` مع قاعدة تسمح لكل
  طالب بالكتابة في مستنده فقط.
- **تحديد عدد الأجهزة** لمنع مشاركة الحساب.
- **Firebase Storage** لملفات الأقسام (حماية كاملة كما شُرح في 5-ب).
